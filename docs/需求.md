# 新增需求

## 20260912

1. 一台主机只运行一个实例。
   — **已实现**（原由 `tauri-plugin-single-instance` 提供，2026-09-13 加固：
   第二实例区分是否系统拉起、补齐最小化窗口还原）。
2. 可以设置开机启动。
   — **已实现**（2026-09-13）。拆为两个独立开关：「开机自动启动」（事实源是操作系统，
   经 `cmd_get_autostart` / `cmd_set_autostart` 直读直写，本地不留副本）与
   「启动时最小化到托盘」（`AppSettings.start_minimized`，对手动启动与开机自启同样生效）。
3. 服务端可以设置最大可以传输的文件或者剪贴板内容最大多大，当超出限制时，客户端弹出提示：文件/剪贴板内容太大，无法传输。
4. 可以设置传输历史保存最新的多少条，超出的删除（界面提醒和缓存的内容）。
   — **已实现**（2026-09-13）。新增 `AppSettings.history_max_entries`，默认 100，`0` = 不限制。
   超出的最旧记录连同其数据库行（四张表）与磁盘缓存文件一并删除。
   两条硬约束：进行中的任务不删；文件仍处于 2 小时剪贴板免疫窗口内的会话本轮跳过。
   触发点为任务落终态后、保存设置后、启动时（启动先把崩溃残留的非终态行复位为 FAILED，
   否则死行会永久占住保留额度）。列表**显示**上限与**淘汰**上限解耦，前者是防御性常量。
5. 可以设置传输任务完成后在界面中保持多久，一段时间后自动在界面中消失。
   — **已实现**（2026-09-13）。新增 `AppSettings.transfer_card_retain_secs`，默认 30 秒，
   `0` = 不自动消失。**只作用于 COMPLETED 卡片**：失败卡片始终保留到手动关闭，
   因为错误 toast 仅 4 秒，卡片再自动消失就没有入口能看到失败原因了。
   仅影响界面卡片，不删历史记录与缓存。
6. 客户端可以设置服务端的一些参数（如最大传输的单个文件大小，同时传输的并发数等）。
7. 同时支持好多个用户。
8. 全程加密。
9. 磁盘缓存文件要定时删除。
   — **已实现**（2026-09-13）。核验发现定时清理早已存在（每小时一次，24h TTL +
   10GB LRU），本轮是把写死的策略参数开放为配置项，而非新建第二套清理：
   `cache_ttl_hours`（默认 24，`0` = 不按时间清理）、`cache_max_size_mb`
   （默认 10240，`0` = 不限容量）、`cache_sweep_interval_minutes`（默认 60，最小 1）。
   同时收敛了「常量与 SQL 字面量两套值」的陷阱：`DEFAULT_TTL` 与
   `CLIPBOARD_LOCK_DURATION` 原本是死代码，真正生效的是 SQL 里的裸数字，
   改常量不会有任何效果且无编译警告；现全部集中到 `core/retention.rs`。
   清理循环改为「先 sweep 后 sleep」以保留「启动即扫」；`sweep` 对齐
   `prune_history` 的三段式，磁盘 IO 不持锁。
10. Bug：在线协同设备的列表中显示的设备运行的版本号跟实际不一致。
    — **已修复**（2026-09-13）。根因是版本号有三份互相独立的字面量：上报给中继
    服务器的、本机信息的、前端标题徽标的，而 Cargo.toml 等早已是 0.1.1。
    统一为 `app_state::APP_VERSION = env!("CARGO_PKG_VERSION")`，编译期取自
    Cargo.toml；前端徽标改读后端上报值。对端列表需等其重连后刷新。
