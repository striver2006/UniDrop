# 瞬贴 (UniDrop) 用户使用手册 (User Guide)

欢迎使用 **瞬贴 (UniDrop)** —— 极速、安全且原生的跨平台剪贴板与文件分发工具。

本文档将引导您从零开始熟悉“瞬贴”的界面操作、网络配置、设备协同以及最核心的**“远端传输完成后直接在本地 Ctrl+V / Cmd+V 粘贴”**的原生剪贴板黑科技体验。

---

## 1. 核心亮点与工作机制

UniDrop 与传统文件传输工具（如网盘、微信文件传输助手、隔空投送）相比，最大的革新在于：
* **原生剪贴板无感装载**：接收端下载校验完毕后，直接将文件句柄注入操作系统剪贴板（Windows `CF_HDROP` / macOS `fileURL` / Linux `text/uri-list`）。您无需在繁琐的“下载文件夹”里翻找，直接在目标目录按 **`Ctrl + V`** (Windows/Linux) 或 **`Cmd + V`** (macOS) 即可瞬间落地粘贴！
* **端到端加密**：内容在本机以 AES-256-GCM 加密后才经中继转发，服务器看不到明文（默认开启，密钥由 PSK 派生）。另有 HMAC 盐化接入、TLS 证书校验、PathGuard 防目录穿越沙盒、整文件 SHA-256 核验。
* **超轻量常驻**：后台常驻仅需 20~30MB 物理内存，低功耗静默运行。

## 2. 首次配置与偏好设置

首次安装并启动 UniDrop 后，客户端会常驻在桌面系统托盘中：

### 2.1 托盘与窗口唤出
* **左键点击托盘图标**：唤出或收起 UniDrop 主面板；
* **右键点击托盘图标**：呼出系统托盘菜单，支持“显示主窗口”与“退出 UniDrop”；
* **窗口拖动**：UniDrop 采用精致现代的无边框设计，鼠标点击主面板顶部深色标题栏区域即可随意拖拽停靠在屏幕任意位置。

> macOS 26 (Tahoe) 用户：如果菜单栏里**看不到图标**，不是安装出了问题，见 [2.2](#22-macos-26-tahoe菜单栏图标不显示的恢复办法)。

### 2.2 macOS 26 (Tahoe)：菜单栏图标不显示的恢复办法

**现象**：应用正常运行（Dock 里有图标、通知照常收到、文件也能正常收发），但屏幕顶部的菜单栏里找不到 UniDrop 的图标。

**原因**：macOS 26 新增了菜单栏准入控制，图标其实已经创建成功、菜单和点击也都正常，只是系统没有分配位置给它。正常安装的用户通常不会遇到——新应用默认就是允许的。真出现了，几乎都是下面这条不太直观的规则导致的：

> macOS 26 会把一个菜单栏图标算在「**启动它的那个应用**」名下。如果你是从某个应用内部（最常见的是终端或代码编辑器）启动的瞬贴，瞬贴的图标就被记在那个应用名下；**那个应用的菜单栏开关一旦是关着的，它名下的图标会被一起挡住**——哪怕瞬贴自己的开关是开着的。

**这不是签名、公证或安装损坏的问题，重装应用、重新下载不会改变它**——请按下面的步骤做。

**处理步骤**（按顺序尝试，做完每步看一眼菜单栏）：

1. 打开 **系统设置 → 菜单栏 → 应用程序**。
2. 在列表里找到 **瞬贴 (UniDrop)**，确认开关是打开的。列表里若出现**多个同名条目**（例如带彩色图标 `UniDrop` 之外还有灰色通用图标的 `unidrop-client`），把灰色的关掉只留彩色的。
3. 列表里**根本找不到** UniDrop：该条目要等应用首次尝试创建菜单栏图标之后才会被系统写入列表，实测约需 1–2 分钟。请稍候再看，或退出应用重新启动一次。
4. 瞬贴自己的开关已开、图标仍不显示——**请检查同一个列表里的其他应用**，把你曾经用来启动过瞬贴的那个应用（终端、代码编辑器等）的开关也打开。这就是上面那条规则在起作用。
5. 之后用 **访达或启动台**打开瞬贴，不要再从其他应用内部启动它，图标的归属不会自动更正。

开关打开的**瞬间**图标就会回来，不需要重启瞬贴，也不需要重启电脑或注销账户。应用内的提示横幅会自行消失。

**修好之前怎么用**：

* **点击 Dock 栏里的瞬贴图标**即可随时唤回主窗口，所有功能都不受影响。
* 如果你开启了「启动即最小化到托盘」，在图标恢复之前，主窗口会在启动几秒后**自动打开**并在顶部显示上述提示。这是刻意设计的——否则菜单栏没有图标、窗口又不显示，你将没有任何入口。窗口里的「下次不要自动打开」可以关掉这个行为（你的「启动即最小化」设置本身不会被修改）。

### 2.3 配置中继服务器与密钥 (PSK)
点击面板右上角的 **齿轮（偏好设置）图标**，弹出“连接与安全偏好”设置窗口：

```text
+------------------------------------------------------+
| 🛡️ 连接与安全偏好                                   [X] |
+------------------------------------------------------+
| 公网中继服务器地址 (WSS/WS)                          |
| [ wss://unidrop.yourdomain.com                     ] |
|                                                      |
| 账号标识 (Account ID)                                |
| [ my_team_sync                                     ] |
|                                                      |
| 预共享密钥 (PSK Secret Key)                          |
| [ ************************************************ ] |
|                                                      |
| [X] 静默自动装载剪贴板                              |
|     免去点击系统通知，传输完成后直接写入系统剪贴板    |
|                                                      |
|            [  取 消  ]     [ 保存配置 ]              |
+------------------------------------------------------+
```

1. **公网中继服务器地址**：
   * 本地测试默认填 `ws://127.0.0.1:8080`；
   * 生产环境填写您自己搭建或团队提供的安全地址（如 `wss://unidrop.yourdomain.com`）。
2. **账号标识 (Account ID)**：
   * 需协同流转的多台设备必须填入**相同的 Account ID**，以归属在同一个安全工作区内。
   * **格式要求**：1–64 个字符，只能使用字母、数字与 `.` `_` `@` `-`。
     不支持中文与空格——服务端按字节匹配账号，而同一个中文名在不同系统上
     可能产生不同的字节形式，看起来一样却会被分进两个互不相通的工作区。
   * 填错时不会静默失败：客户端顶部会出现红色横幅，写明具体的格式规则。
3. **多账号下的保留策略**（若这台机器上会切换多个账号）：
   * **传输历史保留条数是「每账号」上限**，不是全库总数。两个账号各留 100 条时，
     库内会有 200 条——这样一个账号频繁传输才不会把另一个账号的历史挤光。
   * **缓存的保留时长与容量上限是「全局」的**：磁盘是共享的物理资源，
     给每个账号各配一份容量就等于超卖。容量触顶时按全局最久未用淘汰，
     被淘汰的只是缓存**文件**，历史记录会保留并显示「缓存已清理」。
   * 切换账号后，上一个账号的历史**不会被删除**，只是看不到；切回去就还在。
   * 从旧版本升级时，此前的历史没有账号归属，会被归给**升级后首次启动时的
     那个账号**。这些记录原本就是混在一起的，无从判断真正的归属。
     若首次启动时账号栏是空的或填了非法值，这次认领会跳过；在设置面板里填入
     合法账号并保存后会立刻补做，老历史当场回来，不需要重启。
4. **预共享密钥 (PSK Secret Key)**：
   * 填入中继服务器预设的高强度密钥字符串。
5. **连接安全**（三档，默认第一档，**请尽量保持默认**）：

   **① 校验公共 CA 证书（推荐）**

   校验服务器的 TLS 证书，确认连上的确实是目标服务器。证书需由公共 CA 签发，
   并且你填的地址要与证书上的域名一致。

   **② 信任指定证书**

   先按公共 CA 校验；不通过时再比对你填入的证书 SHA-256 指纹，命中即放行。
   用于**自签证书**与 **IP 直连**这两类部署——它们的证书是合法的，
   只是公共根证书库不认识、或者名字对不上。

   在服务器上取指纹：

   ```bash
   openssl x509 -fingerprint -sha256 -noout -in cert.pem
   ```

   整行输出可以直接粘贴进设置（带 `SHA256 Fingerprint=` 前缀和冒号都能识别）。
   连接失败时，错误横幅的「详情」里会显示**客户端实际看到的**指纹——
   请与服务器上那一串核对一致后再填入。**两者不一致就意味着中间有人**，
   这一步核对正是这一档的安全性所在。

   代价要说清：**指纹匹配的证书将被信任，不再检查域名与有效期**。
   这正是它能用于 IP 直连的原因，也是它相对第一档放弃掉的那部分保证。
   但对固定的一台服务器而言，"钉住这张证书"比"接受任意公共 CA 签发的任意证书"
   其实更严格。

   > **可以填多条，每行一条。** 任一命中即放行。证书轮换期间新旧指纹并存，
   > 就不必掐着时间点同步更新每一台设备。

   ⚠️ **用公共 CA 证书配这一档的话，指纹会随证书续期失效**（Let's Encrypt
   是 90 天一轮），届时所有设备同时连不上。维护方案见
   [第 6 节「证书指纹的维护」](#6-证书指纹的维护只有信任指定证书档需要)——
   只能用 IP 直连时，那一节推荐换成十年期自签证书，一次配置不用再管。

   **③ 允许不安全连接（不校验）**

   完全跳过证书校验。代价：任何位于网络中间的人只要出示一张自签证书就能冒充
   服务器，读取经由它传输的剪贴板内容与文件。连接仍然是加密的，
   但**加密的对端是谁不再有任何保证**。绝大多数情况下第二档就够了，
   不需要用到这一档。

   **连不上时先看错误提示说的是哪一种**——各种成因的正确处置完全不同：

   | 提示 | 含义 | 正确处置 |
   | --- | --- | --- |
   | 证书域名不匹配 | 证书**有效**，只是签发给了别的名字 | 先确认那个域名确实是你自己的服务器，再把地址改过去。**不要**为此关校验 |
   | 证书签发者未知 | 自签或企业内部 CA | 换受信任 CA 的证书，或用第二档填指纹 |
   | 证书已过期 | 证书到期了 | 服务端续期（`certbot renew`） |
   | 证书尚未生效 | 多半是**本机系统时间**不对 | 先校对本机时间 |
   | 证书格式不受支持 | X.509 v1 | 必须重签，见下 |

   最常见的一种是第一行：用 **IP 地址**连一台证书只签给域名的服务器。
   这时证书本身完全受信任，换成域名就能连上，**不需要降低任何安全设置**。

   > ⚠️ 但改地址之前请先确认：**列出的那个域名确实是你自己的服务器。**
   > 证书由公共 CA 签发，只说明对方拥有那个域名，**不说明那台机器是你的**。
   > 一个位于中间的攻击者同样可以出示一张自己域名的合法证书来触发这个提示，
   > 你照着改地址就等于主动连了过去。域名不认识时，不要改地址，也不要关校验。
   > 可以展开横幅的「详情」，用里面的证书指纹与服务器上的做一次核对。

   * **自签证书必须是 X.509 v3**——这一条选哪一档都绕不过：客户端在**解析**
     阶段就会拒绝 v1 证书，那一步早于任何校验逻辑。
     实测报错为 `invalid peer certificate: ... UnsupportedCertVersion`。
   * **SAN（主机名）只有在第一档下才需要**：它服务于主机名校验，
     而第二、三档都不查名称。不过下面这条命令一次把两个条件都满足。
   * macOS 自带的 LibreSSL 用 `openssl req -x509` 默认生成的正是 v1，需要显式加
     扩展：

     ```bash
     openssl req -x509 -newkey rsa:2048 -keyout key.pem -out cert.pem \
       -days 365 -nodes -subj "/CN=your.host" \
       -addext "subjectAltName=DNS:your.host,IP:1.2.3.4"
     ```

     用 `openssl x509 -in cert.pem -noout -text | grep Version` 确认输出是
     `Version: 3 (0x2)`。

6. **端到端加密**（默认**开启**，建议保持开启）：
   * 开启后，内容在本机加密后才交给中继服务器转发，**服务器、云厂商或拿到服务器
     权限的人都看不到明文**。传输的文件名、内容哈希与预览摘要同样被加密。
   * 密钥不需要另外配置：由你填的 **PSK** 按每次传输派生，所以**两端 PSK 必须一致**。
     不一致时对方会直接拒收并提示「两端密钥可能不一致」，而不是传到一半失败。
   * **PSK 的强度决定加密的强度**。它现在不只是接入凭据，还是解开内容的钥匙，
     请使用足够长的随机字符串。
   * 对端客户端版本过旧时，本次传输会**回落为不加密**并在界面上明确提示。
     不会静默发生——但也意味着那次传输的内容服务器是能看到的。
   * 它**不保证**以下几件事，请勿据此做更强的假设：
     * **前向保密**：PSK 长期不变，一旦泄露，此前被录下的流量都能解开；
     * **设备丢失**：PSK 以明文保存在本机配置里，拿到设备就能解开历史内容；
     * **设备之间互相隔离**：同一 PSK 下所有设备共用同一套密钥，彼此可解；
     * **防止被强制降级**：协商信息经过服务器，恶意服务器可以把传输打回不加密
       （界面会提示，但无法区分是对端老还是被做了手脚）；
     * **本地存储加密**：本机的历史数据库与缓存文件仍是明文。
   * 服务器始终能看到的元数据：谁传给谁、时间、总大小、条目数与每个条目的大小、
     类型是文本还是文件。这是服务端限额检查的必要输入，与加密不可兼得。
7. **静默自动装载剪贴板**（强烈推荐勾选）：
   * 开启后，远端传来的文件一经下载核验完成，无需手动点击，直接写入本地系统剪贴板。
8. 点击 **“保存配置”**，客户端将即时热更新配置并自动重新建立安全连接，无需重启客户端。

> [!TIP]
> 如果顶部出现红色横幅提示 **“鉴权失败: signature mismatch / timestamp expired”**，说明密钥填写有误或本机系统时间与服务器误差超过 60 秒，请点击“检查密钥”重新校对。

## 3. 在线设备发现与状态感知

当配置生效且与中继服务器建立 WSS 长连接后：
* 主面板下方的连接状态将亮起绿灯：**“PSK 接入安全就绪”**；
* 本机信息行展示：`本机: 主机名 (操作系统类型)`；
* “在线协同设备”区域将实时列出当前局域网或公网中同一 Account ID 下的其他在线设备：
  * 每台设备展示：主机名、系统标识徽章（如 `MAC` / `WINDOWS` / `LINUX`）、在线状态绿点；
  * 右侧带有 **“发送文件”** 操作按钮。

## 4. 发送文件与目录操作

### 方式一：拖拽文件（最便捷）
1. 在“在线协同设备”列表中，找到要接收文件的目标设备，点击 **“发送文件”**；
2. 弹出“发送文件”窗口；
3. 直接从系统访达（Finder）或文件资源管理器中，将一个或多个文件/文件夹**拖拽到弹窗中**；
4. 弹窗将立即捕获路径并显示在“待发送列表”中；
5. 点击 **“开始发送”**，后台将自动进行哈希计算、分块封包，并通过流水线滑动窗口高速中继发往目标端。

### 方式二：手动输入或粘贴绝对路径
1. 在弹窗输入框中，直接粘贴目标文件的绝对路径（如 `/Users/name/Documents/report.pdf` 或 `D:\Photos\photo.jpg`）；
2. 点击 **“添加”** 或直接按下键盘 **`Enter` 回车键**；
3. 支持添加多个文件或目录进行批量打包传输；
> [!NOTE]
> **关于文件夹传输说明**：当前 v0.1.0 版本核心聚焦于常规单/多文件的高速无感流转；若直接选择文件夹，客户端为保证路径安全性会自动跳过目录项。如需分发大型目录，建议先压缩为 `.zip` 或 `.tar` 后发送。

## 5. 接收文件与剪贴板无感粘贴落地

当远端设备向您发起文件流转时：

1. **请求与进度感知**：
   * 屏幕右上角将弹出系统原生提示：`收到传输请求: X 个文件`；
   * UniDrop 主面板上方的“当前传输”列表自动展示该会话条目，并实时刷新动态传输进度条（已传输字节数、百分比、传输中状态）。
2. **下载核验**：
   * 接收端自动通过流水线滑动窗口拉取分块，并由 PathGuard 过滤恶意逃逸路径，落入安全沙盒缓存目录，完成 SHA-256 全量哈希比对。
3. **原生剪贴板注入与落地**：
   * **情况 A（已勾选“静默自动装载剪贴板”）**：
     * 传输进度显示 100% 完成后，系统托盘弹出绿色成功通知：`传输完成，已装载至系统剪贴板`。
     * **此时您只需要：打开任意文件夹或桌面，直接按下 `Ctrl + V`（Windows/Linux）或 `Cmd + V`（macOS），文件即刻从剪贴板粘贴落地！**
   * **情况 B（未勾选自动装载）**：
     * 传输完成后，卡片上将显示 **“装载到剪贴板”** 按钮；
     * 鼠标点击该按钮，即可随时将该会话的文件装入系统剪贴板，随时随处粘贴。

## 6. 证书指纹的维护（只有「信任指定证书」档需要）

公共 CA 签发的证书有效期很短（Let's Encrypt 是 90 天），**续期之后指纹必然改变**，
原先填在客户端里的那一串随即失效——表现是所有设备同时连不上，而服务器看起来
一切正常。这一节讲怎么让它不发生。

先判断你属于哪种情况：

| 你的部署 | 建议方案 |
| --- | --- |
| 能用域名，证书由公共 CA 签发 | **不要用指纹档**，用第一档「校验公共 CA 证书」，续期完全无感 |
| 只能用 IP 直连（例如域名未备案），但服务器上是公共 CA 证书 | 方案 A：定期更新指纹 |
| 只能用 IP 直连，且这个端口只给 UniDrop 用 | **方案 B：换长期自签证书**，一次配置十年不用管 |

### 6.1 方案 A：证书续期后更新指纹

**第一步：让服务器在每次续期后自动记下新指纹。**

新建 `/etc/letsencrypt/renewal-hooks/deploy/unidrop-fingerprint.sh`：

```bash
#!/bin/sh
# certbot 续期成功后自动执行。只记录指纹，**不 reload Nginx**——
# 留出一段时间窗口，让各台设备先把新指纹填进去，再切换服务端证书。
CERT="/etc/letsencrypt/live/你的域名/cert.pem"
LOG="/var/log/unidrop-cert-fingerprint.log"

FP=$(openssl x509 -fingerprint -sha256 -noout -in "$CERT" | sed 's/.*=//')
echo "$(date -Iseconds)  新证书指纹：$FP" >> "$LOG"
```

赋予执行权限：

```bash
sudo chmod +x /etc/letsencrypt/renewal-hooks/deploy/unidrop-fingerprint.sh
```

certbot 默认在到期前 30 天续期，所以你有大约一个月的窗口，不必掐着时间。

**第二步：取出新指纹，追加到每台设备。**

```bash
sudo tail -n 3 /var/log/unidrop-cert-fingerprint.log
```

在「设置 → 连接安全 → 信任指定证书」的输入框里**另起一行**贴上新指纹，
**保留旧的那一行**。两条并存期间新旧证书都能连，这正是支持多行的用处——
你不需要让所有设备在同一时刻完成更新。

**第三步：切换服务端证书。**

```bash
sudo nginx -t && sudo systemctl reload nginx
```

> ⚠️ 忘记 reload 是最常见的坑：证书文件已经换了，Nginx 却还在用内存里的旧证书。
> 这时客户端看到的仍是旧指纹，你会以为新指纹填错了。

**第四步：确认所有设备都连上之后**，回到设置里删掉旧指纹那一行。

留着不删也能用，但它意味着「那张已经作废的证书仍然被信任」——
万一旧私钥泄漏，攻击者可以拿它冒充服务器。清理掉是干净的做法。

**日历提醒**：证书 90 天到期、提前 30 天续期，所以大约**每两个月**要走一次
这个流程。可以在服务器上加一条 cron 提前提醒自己：

```bash
# 每周一检查一次，剩余有效期少于 35 天就提醒
0 9 * * 1 openssl x509 -checkend $((35*86400)) -noout \
  -in /etc/letsencrypt/live/你的域名/cert.pem \
  || echo "UniDrop 证书即将续期，请准备更新客户端指纹"
```

### 6.2 方案 B：换成长期自签证书（推荐给 IP 直连）

如果 UniDrop 用的是独立端口（例如 58921），而这个端口不对浏览器提供服务，
那么公共 CA 证书对它其实没有意义——你反正用 IP 连，走不了域名校验，
只能靠指纹。**既然如此，不如换一张有效期十年的自签证书，指纹十年不变。**

> 自签证书在这个用法下并不比公共 CA 证书弱。公共 CA 证明的是「对方拥有那个
> 域名」，而你要确认的是「对方是我那台服务器」——指纹直接钉住了后者，比前者
> 更贴题。前提是你**在服务器上**取指纹，而不是从客户端看到什么就信什么。

动手前先确认那张公共 CA 证书有没有别的用途。逐个端口看它是否真在提供 HTTPS：

```bash
# 在任意一台能访问服务器的机器上执行
echo | openssl s_client -connect 你的服务器IP:443 2>/dev/null \
  | openssl x509 -noout -subject -dates
```

能打印出证书信息，说明 443 上确实有 HTTPS 在用它，那就保留续期、只给 UniDrop
那个端口换自签证书。若报 `no peer certificate available` 或没有输出，说明那个
端口上并没有在用它——这种情况下整张公共 CA 证书就只为 UniDrop 存在，
换掉零损失，还能顺便省掉 certbot 的续期维护。

> 只用 `nc -z` 或 `telnet` 测端口通不通是**不够的**：云服务商的安全组与网络
> 设备常让放行端口的 TCP 握手看起来成功，而后面并没有进程在监听。
> 要判断"有没有服务"，得让它真的说句话——上面那条 openssl 或一次 `curl -i`。

#### 操作顺序（按这个顺序做，可以零中断）

关键在于**先让客户端认识新证书，再切换服务端**。顺序反了的话，切换完成到各台
设备填上新指纹之间，所有设备都连不上。

**第 1 步：生成证书**（不影响正在运行的服务）

```bash
sudo mkdir -p /etc/nginx/ssl
sudo openssl req -x509 -newkey rsa:2048 -nodes -days 3650 \
  -keyout /etc/nginx/ssl/unidrop.key \
  -out /etc/nginx/ssl/unidrop.crt \
  -subj "/CN=UniDrop" \
  -addext "subjectAltName=IP:你的服务器IP,DNS:你的域名"
sudo chmod 600 /etc/nginx/ssl/unidrop.key
sudo chmod 644 /etc/nginx/ssl/unidrop.crt
```

SAN 里同时写上 IP 与域名（有域名的话）：指纹档本来就不检查名称，多写无害，
将来若改用域名访问也不必重签。

**第 2 步：确认是 X.509 v3**

```bash
openssl x509 -in /etc/nginx/ssl/unidrop.crt -noout -text | grep -E "Version|Not After"
# 必须是 Version: 3 (0x2)
```

客户端在**解析**阶段就会拒绝 v1 证书，那一步早于任何校验逻辑，选哪一档都绕不过。
OpenSSL 1.1.1 以上加了 `-addext` 就会生成 v3；老版本或没加这个参数会产出 v1。

**第 3 步：取指纹**

```bash
sudo openssl x509 -fingerprint -sha256 -noout -in /etc/nginx/ssl/unidrop.crt
```

**第 4 步：先把新指纹填进每一台客户端**，在原有那行下面**另起一行**，
旧的先留着。此时服务端还是旧证书，新指纹不匹配任何东西，不影响当前连接——
这正是先填的意义。

**第 5 步：切换 Nginx 并重载**（先建回滚点）

```bash
sudo cp -a /etc/nginx/conf.d/unidrop.conf /etc/nginx/conf.d/unidrop.conf.bak-$(date +%Y%m%d-%H%M%S)
```

把 UniDrop 那个 `server` 块的两行证书路径指过去。**只改这一个 server 块**——
如果别的端口上还有网站在用原来的公共 CA 证书，那部分保持不动：

```nginx
server {
    listen 58921 ssl;
    http2 on;

    ssl_certificate     /etc/nginx/ssl/unidrop.crt;
    ssl_certificate_key /etc/nginx/ssl/unidrop.key;
    # ……其余 location 配置保持不变
}
```

```bash
sudo nginx -t && sudo systemctl reload nginx
```

`nginx -t` 不通过就不要 reload，直接从备份恢复。

**第 6 步：带外核对**

在能访问服务器的机器上取一次实际握手到的证书，与服务器上的文件比对：

```bash
echo | openssl s_client -connect 你的服务器IP:58921 2>/dev/null \
  | openssl x509 -fingerprint -sha256 -noout
```

两串一致，说明新证书已生效且链路上没有中间人。各设备此时应当自动重连成功
（连接 actor 最长 30 秒退避一次），确认无误后再把旧指纹那一行删掉。

#### 收尾：停用 certbot 并清理旧证书

换完之后 certbot 就没有存在的必要了。**先备份再删**，万一将来要用还能还原：

```bash
# 1. 归档备份（含私钥，权限收紧）
sudo tar czf /root/letsencrypt-backup-$(date +%Y%m%d-%H%M%S).tar.gz -C /etc letsencrypt
sudo chmod 600 /root/letsencrypt-backup-*.tar.gz

# 2. 停用自动续期
sudo systemctl disable --now certbot-renew.timer
# 如果是 cron 方式：sudo crontab -e 删掉 certbot 那一行

# 3. 确认 Nginx 已不再引用它，再删证书
sudo grep -rn "letsencrypt" /etc/nginx/nginx.conf /etc/nginx/conf.d/*.conf
sudo certbot delete --cert-name 你的域名
```

用 `certbot delete` 而不是手工 `rm`：它会把 `live/`、`archive/`、`renewal/`
三处一并清理干净，手工删容易留下半截配置，下次装 certbot 时报错。

> 留意 `sudo ls /root/xxx-*.tar.gz` 这类写法**会失败**：通配符由当前 shell 展开，
> 而普通用户读不了 `/root`，展开不出来就把字面量传给了 ls。
> 要用 `sudo sh -c "ls /root/xxx-*.tar.gz"`。

#### 顺带：关掉不再需要的端口

certbot 用的是 HTTP-01 验证（`authenticator = standalone` 或 `webroot`）的话，
它依赖 80 端口。停用 certbot 之后，如果 80 上没有别的业务，可以一并关掉，
减少暴露面——公网上的扫描器会持续探测 80 上的 `.env`、`.bak`、`.conf` 这类文件。

先确认 80 上确实没有业务：

```bash
sudo ss -tlnp | grep -E ':80\b'                    # 谁在监听
sudo grep -rn "listen.*80" /etc/nginx/nginx.conf /etc/nginx/conf.d/
sudo ls /etc/nginx/default.d/                      # 默认 server 常 include 这里
```

> ⚠️ **看访问日志判断「有没有人在用」时有个坑。**
>
> Nginx 默认只在 `http` 块里配一次 `access_log`，**所有 server 块共享同一个
> 文件**，而 `combined` 格式**不记录端口号**。于是 58921 上的 UniDrop 流量
> 也会写进同一份日志——你会在里面看到 `/ws/control` 返回 `101`
> （WebSocket 升级成功）而误以为有客户端在走 80 明文连接，
> 进而不敢关 80。
>
> 要分清来自哪个端口，临时加一条带 `$server_port` 的日志格式：
>
> ```nginx
> log_format probe '$remote_addr :$server_port $request $status';
> access_log /var/log/nginx/probe.log probe;
> ```
>
> `reload` 后观察一会儿，就能看到每条请求各自落在哪个端口。查完把这两行撤掉。

确认无误后，注释掉默认站点的整个 `server` 块（在 `/etc/nginx/nginx.conf` 里）：

```nginx
# --- 默认站点已停用：80 端口不再监听 ---
#    server {
#        listen       80;
#        listen       [::]:80;
#        server_name  _;
#        root         /usr/share/nginx/html;
#        ……
#    }
```

**必须注释整个 server 块，不能只注释那两行 `listen`**——Nginx 对没有 `listen`
指令的 `server` 块会默认监听 80，只注释 listen 等于什么都没做。

```bash
sudo nginx -t && sudo systemctl reload nginx
sudo ss -tlnp | grep nginx        # 确认只剩 UniDrop 那个端口
```

> `reload` 之后短时间内 `ss` 可能仍显示 80 在监听，那是旧 worker 进程在优雅
> 退出（`nginx: worker process is shutting down`），它们还持有旧的监听描述符。
> 等十几秒再看即可，不必重启 Nginx。

走完这套流程后，指纹十年不变，certbot、80 端口、每两个月一次的指纹更新
这三件事可以一起从维护清单里划掉。证书到期前换一张新的，重走一遍即可。

### 6.3 指纹核对：别在被攻击的链路上核对

无论哪个方案，取指纹都要在**服务器上**做（SSH 登录后对证书文件执行 openssl）。

客户端错误横幅的「详情」里也会显示一串指纹，那是**客户端实际看到的**证书。
它的用途是拿来和服务器上那一串**比对**，不是直接复制粘贴就完事——
如果链路上真有中间人，你从横幅复制到的正是中间人的指纹，填进去等于把门打开。

两串一致，才说明链路干净、可以填入。

## 7. 本地缓存与空间管理

* **沙盒缓存目录**：
  * UniDrop 会将中转的文件临时存放在系统专用的应用程序缓存沙盒内：
    * **macOS**: `~/Library/Caches/UniDrop/cache/`
    * **Windows**: `%LOCALAPPDATA%\UniDrop\cache\`
    * **Linux**: `~/.cache/unidrop/cache/` (或 `$XDG_CACHE_HOME/unidrop/cache/`)
* **剪贴板免疫锁与自动老化清理**：
  * **2 小时剪贴板免疫保护锁**：凡是被装载至系统剪贴板的文件，在 2 小时内受强制免疫保护，任何自动清理进程均不会将其误删，防止用户尚未粘贴时文件被回收；
  * **定期 GC 与容量水位保护**：客户端后台守护进程每小时运行一次清理。默认 TTL 为 24 小时；当缓存总量达到 10GB 高水位线时，将自动按 LRU 顺序缩容清理至 8GB 安全低水位。

## 8. 常见问题排查与 FAQ

### Q1: 在线协同设备列表中看不到另一台电脑？
1. 请确认两台设备的 **服务器地址 (Server URL)**、**Account ID** 和 **预共享密钥 (PSK)** 完全一致；
2. 检查两台设备是否都能正常访问中继服务器（例如可以在浏览器或终端测试 `http://server_ip:8080/healthz` 是否返回 200 OK）；
3. 点击主界面右上角的 **“刷新”** 按钮主动拉取最新的在线列表。

### Q2: 提示“传输完成”，但按 Ctrl+V / Cmd+V 没有反应？
1. **系统权限检查**：
   * 在 macOS 上，请确认已在“系统设置 -> 隐私与安全性 -> 辅助功能”中允许了 UniDrop 访问；
   * 在 Linux 上，请确认已根据安装手册安装了 `xclip`（X11 用户）或 `wl-clipboard`（Wayland 用户）。
2. **剪贴板被后续操作覆盖**：
   * 如果在传输完成之后，您又在本地按了 `Ctrl+C` 复制了其他文字或文件，剪贴板会被新内容覆盖。此时只需在 UniDrop 主面板的传输记录中，重新点击 **“装载到剪贴板”** 按钮即可重新恢复。

### Q3: 传输超大文件（数 GB）会不会把内存撑爆？
* 不会。UniDrop 无论在服务端还是客户端，均采用 **4MB 分块流式管道（Streaming Pipeline）** 和固定大小的滑动窗口设计，零磁盘内存透传。传输时内存开销平稳受控在 30MB~50MB 左右，支持大文件稳定无损流转。

### Q4: 升级后连不上，横幅提示证书有问题？

先展开横幅上的 **「详情」**——各档失败的正确处置完全不同，详见
[第 2 节「连接安全」](#2-首次配置与偏好设置)的对照表。

最常见的一种是 **「证书域名不匹配」**：你在地址栏填的是 **IP**，
而证书是签给**域名**的。此时证书本身完全有效，把地址改成证书上的域名即可，
**不需要关闭证书校验**。

### Q5: 昨天还能连，今天所有设备突然都连不上了？

如果你用的是「信任指定证书」档、且服务器上是公共 CA 证书，**多半是证书续期了**。
续期后指纹改变，原先填的那一串随即失效——特征是所有设备同时失效，而服务器
本身一切正常。

在服务器上确认证书是不是刚换过：

```bash
openssl x509 -dates -noout -in /etc/letsencrypt/live/你的域名/cert.pem
```

`notBefore` 若是最近的日期，就是它。按
[第 6 节「证书指纹的维护」](#6-证书指纹的维护只有信任指定证书档需要)
取新指纹更新即可；想彻底免除这项维护，同一节的方案 B 给了做法。

### Q6: 反馈问题时需要提供什么？

客户端日志，它会告诉我们连接是在哪一步失败的：

* **macOS**：`~/Library/Logs/com.unidrop.client/unidrop.log`
* **Windows**：`%LOCALAPPDATA%\com.unidrop.client\logs\unidrop.log`
* **Linux**：`~/.local/share/com.unidrop.client/logs/unidrop.log`

日志会自动轮转，最多占用约 4 MB。其中的会话令牌已做脱敏（显示为
`token=<redacted>`），但下列内容是明文，介意的话发送前请自行裁剪：

* 服务器地址与账号标识；
* **本地文件路径与文件名**（传输出错时会记录，用于定位是哪个文件失败）。
